# 07 - Overnight OS Audit

Run in the evening before sleep.

This phase turns today's lessons into system memory without overcomplicating the OS.

## Three Questions

1. What rule was closest to breaking today?
2. What pattern from today is worth watching again?
3. What one system upgrade would have made today cleaner?

## Step 1 - Rulebook Review

Open [08-personal-rulebook.md](08-personal-rulebook.md).

Write:

```text
Rule closest to breaking today:
Why it almost broke:
Tomorrow I will specifically protect against:
```

## Step 2 - Extract One Reusable Pattern

A pattern qualifies only if:

- it appeared 3 or more times with a positive outcome, or it prevented a clear mistake
- it can be written as a testable rule
- it improves setup filtering or review quality
- it reduces rule-breaking or hesitation

Candidate pattern:

```text
Pattern:
Where it appeared:
Why it mattered:
What rule it might become:
Evidence count:
```

Do not add it to the rulebook yet unless it passes the backtest protocol.

## Step 3 - One System Upgrade Hypothesis

Use this format:

```text
If I add [rule/filter/checklist item], then [specific outcome], because [what today showed me].
```

Backtest requirement:

- minimum 10 quick chart checks before adding as a temporary filter
- 50-100 instances before adding as a live setup rule

## Prompt F - Overnight OS Audit

```text
Here is my current personal rulebook: [PASTE 08-personal-rulebook.md]. Today's session summary: [PASTE daily score + key observations]. Which rule was closest to being broken today? What one new system would have improved today's execution -- and does it meet the 10-instance backtest threshold before I add it? Give me one sentence for tomorrow's protection focus.
```

## Tomorrow Protection Focus

```text
Tomorrow I protect:
```

Only one.
